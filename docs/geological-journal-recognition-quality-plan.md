# План улучшения качества распознавания геологических журналов

## Цель

Повысить точность извлечения рукописных и печатных данных из полевых
геологических журналов без дообучения OCR- или LLM-моделей.

Основные метрики:

- точность распознавания значений по каждому полю;
- доля полностью корректных строк;
- доля значений, требующих ручного исправления;
- полнота: сколько строк исходной страницы попало в результат;
- точность отметки сомнительных значений в `uncertainties`;
- среднее время ручной проверки одной страницы.

## Текущее ограничение

Сейчас OCR-этап возвращает сплошной текст страницы. Координаты слов, строк,
табличных блоков и ячеек не используются. Для широких журналов это приводит к
потере связи между значением и исходной колонкой. Текстовая модель вынуждена
восстанавливать структуру таблицы только по порядку фрагментов текста.

## Этап 1. Подготовить эталонный набор

1. Выбрать 30–50 страниц разных типов:
   - чёткие сканы;
   - фотографии с перспективой;
   - слабый контраст и пожелтевшая бумага;
   - разные почерки;
   - разные формы таблиц.
2. Вручную подготовить правильный JSON для каждой страницы.
3. Разделить страницы на постоянный проверочный и рабочий наборы.
4. Сделать локальный оценщик качества по отдельным колонкам.

Без фиксированного набора нельзя объективно определить, улучшил ли очередной
этап распознавание.

## Этап 2. Предобработка изображения

Перед OCR автоматически создавать улучшенную копию изображения:

- исправлять перспективу фотографии;
- определять и устранять наклон страницы;
- обрезать пустые поля;
- нормализовать освещение;
- переводить изображение в оттенки серого;
- повышать локальный контраст;
- подавлять шум и фон пожелтевшей бумаги;
- увеличивать мелкий текст в 2–3 раза;
- аккуратно усиливать линии и символы без потери рукописных штрихов.

Оригинал всегда хранить без изменений. OCR запускать по оригиналу и
предобработанной версии, если качество исходника ниже заданного порога.

## Этап 3. Сохранять геометрию OCR

Вместо одного `fullText` получать и сохранять:

- текстовые блоки;
- строки;
- отдельные слова;
- bounding box каждого элемента;
- оценку уверенности, если она доступна;
- номер страницы и порядок чтения.

На основе координат определять:

- горизонтальные границы строк;
- вертикальные границы колонок;
- принадлежность слова конкретной ячейке;
- многострочные описания породы;
- объединённые ячейки.

В LLM передавать не сплошной текст, а структурированное представление:
координаты колонок, строки и содержимое предполагаемых ячеек.

## Этап 4. Распознавать страницу по областям

После определения сетки отдельно обрабатывать группы колонок:

1. дата, диаметр, глубина от/до;
2. проходка и выход керна;
3. описание породы;
4. интервалы опробования и номера проб;
5. примечания.

Для сложных страниц использовать второй OCR-проход по увеличенным фрагментам
конкретных ячеек. Это особенно важно для мелких чисел и рукописного описания.

## Этап 5. Несколько OCR-проходов

Запускать разные режимы OCR:

- рукописный текст;
- таблица;
- страница.

Результаты сопоставлять по координатам. Если варианты совпадают, повышать
уверенность. Если расходятся, выбирать значение по контексту и правилам либо
добавлять поле в `uncertainties`.

Полный повторный проход применять только для сложных страниц, чтобы не
увеличивать стоимость и время обработки всех документов.

## Этап 6. Улучшить структурирование через LLM

1. Добавить в системный prompt реальные примеры:
   `OCR + координаты → правильный JSON`.
2. Передавать заголовки и предполагаемые границы колонок.
3. Добавить словарь геологических терминов и распространённых сокращений.
4. Запретить перенос значения между колонками без достаточного основания.
5. Требовать объяснимую отметку каждого сомнительного поля в
   `uncertainties`.
6. Для конфликтных значений передавать несколько OCR-кандидатов.

## Этап 7. Детерминированная проверка результата

После LLM проверять результат обычным кодом:

- `depth_to_m >= depth_from_m`;
- `drilling_run_m ≈ depth_to_m - depth_from_m`;
- `core_recovery_m <= drilling_run_m`;
- `core_recovery_pct` находится в диапазоне 0–100;
- глубины соседних строк логически продолжают друг друга;
- диаметр находится в реалистичном диапазоне;
- дата соответствует допустимому формату;
- интервалы проб не выходят за пределы строки;
- обязательные числовые поля не заменены текстом.

Система не должна молча придумывать исправления. Если правило выявило
конфликт, исходное значение сохраняется либо заменяется на `null`, а причина
добавляется в `uncertainties`.

## Этап 8. Профили шаблонов

Для повторяющихся форм журналов хранить профиль:

- расположение колонок;
- названия и сокращения заголовков;
- ожидаемые типы данных;
- правила объединённых ячеек;
- характерные диапазоны значений.

Профиль определять автоматически по заголовку и геометрии страницы. В
интерфейсе оставить возможность вручную выбрать другой шаблон.

## Этап 9. Использовать пользовательские исправления

Не обучая модель, можно улучшать следующие распознавания:

- собирать анонимизированный словарь частых OCR-ошибок;
- сохранять варианты написания геологических терминов;
- находить повторяющиеся исправления для конкретного шаблона;
- использовать подтверждённые строки как few-shot примеры;
- не передавать данные одного пользователя другому без явного разрешения.

## Рекомендуемый порядок реализации

1. Эталонный набор и оценщик качества.
2. Предобработка изображения.
3. Получение координат OCR.
4. Разбиение страницы на строки и колонки.
5. Детерминированные геологические проверки.
6. Словарь терминов и few-shot примеры.
7. Повторный OCR сложных ячеек.
8. Профили шаблонов.
9. Использование подтверждённых пользовательских исправлений.

Наибольший ожидаемый прирост дадут сохранение геометрии OCR, предобработка
изображения и распознавание отдельных областей страницы.
